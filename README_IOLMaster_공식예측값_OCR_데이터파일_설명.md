# IOLMaster 공식 예측값 OCR 데이터 파일 설명

이번에 공유드리는 세 파일은 IOLMaster 검사 화면 JPG 총 **38,226페이지**에서 공식별 IOL 도수와 예상 굴절값을 OCR로 추출한 원시 데이터입니다.

전체적으로는 다음 구조입니다.

- `pilot_summary.json`: 전체 추출 작업의 요약
- `all_pages.csv`: JPG 한 페이지당 한 행의 처리·품질 정보
- `formula_rows.csv`: 공식표에서 읽은 IOL 도수와 예상 굴절값

중요하게, `formula_rows.csv`의 약 90만 행은 환자 90만 명을 의미하지 않습니다. 한 검사에서 양안, 여러 공식, 여러 IOL 도수가 각각 별도 행으로 저장되기 때문에 행 수가 크게 증가한 것입니다.

## 1. `pilot_summary.json`

전체 OCR 작업이 정상적으로 완료됐는지를 한눈에 확인하는 요약 파일입니다. 파일명에는 과거 개발 단계의 명칭인 `pilot`이 남아 있지만, 현재 내용은 일부 표본이 아니라 **전체 자료**에 대한 결과입니다.

주요 수치는 다음과 같습니다.

- 검사 건수: **5,194건**
- 처리된 JPG 페이지: **38,226페이지**
- 공식 예측값 추출 행: **908,037행**
- 공식표가 하나 이상 확인된 검사: **4,616건**
- 페이지 처리 완료율: **100%**

공식이 발견된 페이지 수는 대략 다음과 같습니다.

- SRK/T: **7,205페이지**
- Hoffer Q: **7,108페이지**
- Haigis: **6,871페이지**
- Barrett Universal II TK: **5,144페이지**

여기서 공식별 숫자는 환자 수가 아니라 해당 공식이 검출된 페이지 수입니다. 한 환자 또는 한 눈에 여러 페이지가 있을 수 있습니다.

`resumed_pages`는 오류나 중복을 의미하지 않습니다. 장시간 OCR 중간에 저장된 체크포인트를 재사용한 페이지 수입니다. 즉, 처음부터 다시 OCR하지 않고 이전 결과를 안전하게 이어받았다는 뜻입니다.

이 파일은 임상 결과를 분석하는 파일이라기보다는 전체 데이터 추출의 완결성과 처리 규모를 확인하는 작업 보고서입니다.

## 2. `all_pages.csv`

JPG 한 페이지를 한 행으로 정리한 페이지 단위 목록입니다. 총 **38,226행**으로 구성되어 있습니다.

각 행에는 다음 정보가 들어 있습니다.

- 비식별화된 검사·환자 토큰
- 검사 연도와 페이지 번호
- 이미지 크기
- 페이지 종류
- 해당 페이지에서 발견된 공식
- OCR 문자 수와 평균 신뢰도
- 페이지 처리 시간
- 추출된 공식 예측값 행 수
- 공식표 구조가 규칙적으로 인식됐는지에 대한 품질 지표

`page_class`는 해당 페이지를 다음과 같이 분류합니다.

- `iolmaster700_formula`: IOLMaster700 공식 계산 페이지
- `iolmaster700_other`: IOLMaster700이지만 공식표가 아닌 페이지
- `iolmaster_legacy_formula`: 구형 IOLMaster 공식 페이지
- `power_formula`: 도수와 공식 예측값이 포함된 기타 형식
- `quantel_ascan`: Quantel A-scan 화면
- `other`: 그 밖의 형식

공식표가 아닌 페이지에서 `extracted_formula_rows=0`으로 나오는 것은 정상입니다. 이 파일의 주된 용도는 특정 검사에서 어떤 페이지가 공식표로 인식됐는지 확인하고, OCR 추출 실패나 특이한 페이지를 찾아내는 것입니다.

따라서 `all_pages.csv`는 임상 통계 분석용 데이터라기보다 **OCR 품질관리와 원본 추적**을 위한 파일입니다.

## 3. `formula_rows.csv`

실제 공식 예측값이 들어 있는 핵심 원시 추출 파일입니다. 약 **170MB**이며 총 **908,037행**입니다.

한 행은 다음을 의미합니다.

> 특정 검사, 특정 눈, 특정 IOL 모델, 특정 공식에서 한 가지 IOL 도수에 대해 표시된 예상 수술 후 굴절값

예를 들어 한 눈의 ZCB00 도수표에 15.0 D부터 25.0 D까지 여러 도수가 표시되어 있다면, 각 도수와 해당 예상 굴절값이 각각 한 행으로 저장됩니다. Hoffer Q, SRK/T, Haigis, Barrett TK가 모두 있으면 같은 눈에 대해 공식별로 다시 여러 행이 생깁니다.

주요 열은 다음과 같습니다.

- `exam_token`, `patient_token`: 비식별화된 검사·환자 식별자
- `eye`: OD 또는 OS
- `formula`: Hoffer Q, SRK/T, Haigis, Barrett Universal II TK 등
- `iol_model_guess`: OCR로 읽은 IOL 모델명
- `iol_power_d`: IOL 도수
- `predicted_refraction_d`: 해당 도수에서 공식이 예측한 굴절값
- `ocr_confidence_min`: 해당 숫자를 읽을 때의 최소 OCR 신뢰도
- `page_index`, `block_id`, `row_index`: 원본 위치 추적용 정보
- `row_crop_*`, `block_crop_*`: 원본 이미지에서 해당 표와 행의 좌표

`iol_power_ocr_text`와 `predicted_refraction_ocr_text`는 화면에서 OCR이 처음 읽은 문자열이고, `_d`가 붙은 열은 이를 분석 가능한 숫자로 변환한 값입니다.

`ocr_confidence_min`은 OCR 숫자 인식의 신뢰도이지 임상적 예측의 신뢰도는 아닙니다. 신뢰도가 높더라도 원본 화면 자체가 잘못됐거나 표의 행이 잘못 연결됐을 가능성은 별도로 확인해야 합니다.

또한 `iol_model_guess`에는 띄어쓰기나 문자 인식 차이가 남아 있을 수 있습니다. 예를 들어 ZCB00의 숫자 0이 문자 O로 읽히거나 제조사 접두어가 함께 들어갈 수 있습니다. 따라서 통계 분석 전에는 ZCB00, ARTIS 등의 표준 모델명으로 정규화하는 과정이 필요합니다.

## 파일을 해석할 때 가장 중요한 주의점

첫째, **908,037행을 환자 수나 눈 수로 해석하면 안 됩니다.** 이는 공식표에 표시된 모든 IOL 도수–예상 굴절 조합의 수입니다.

둘째, 공식 간 비교는 반드시 다음 조건이 동일해야 합니다.

- 같은 검사
- 같은 눈
- 같은 IOL 모델
- 같은 IOL 도수

예를 들어 Hoffer Q 20.0 D와 Haigis 21.0 D를 직접 비교하면 안 됩니다.

셋째, 이 세 파일에는 아직 biometry OOD 점수나 수술 후 1개월 실제 굴절값이 들어 있지 않습니다. 이 파일들은 OCR 원시 추출 계층이며, 이후 다음 과정을 거쳐 최종 분석 데이터가 만들어집니다.

1. 공식명과 IOL 모델명 정규화
2. Haigis 예상값이 0~-0.50 D가 되는 IOL 도수 선택
3. ZCB00 우선, 저도수에서는 ARTIS 보조 사용
4. 동일 도수의 Hoffer Q, SRK/T, Haigis, Barrett TK 비교
5. IOLMaster700 biometry 및 frozen OOD 점수 결합
6. 큰 공식 불일치와 낮은 OCR 신뢰도 사례의 원본 화면 확인

## 개인정보 및 공유 범위

공유 파일에는 실제 환자번호, 이름, 생년월일이 포함되어 있지 않고 `exam_token`, `patient_token`으로 비식별화되어 있습니다.

다만 연구용 의료 데이터에서 파생된 자료이므로, 비식별 파일이라도 **연구진 내부의 승인된 저장 공간에서 관리하고 외부 공개 저장소에는 별도 승인 없이 업로드하지 않는 것**이 안전합니다.
